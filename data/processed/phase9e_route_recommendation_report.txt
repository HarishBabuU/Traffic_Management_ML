  3. ROUTE MODEL
     Each route has: route_id, segment_order, road_id, road_name,
     optional distance_km, optional travel_time_minutes, data_mode.
     If a distance or travel time is unavailable it is NOT estimated
     and is left explicitly unavailable/blank. Fictional mock
     distances are used only to exercise the weighting logic.

  4. ROUTE SCORE
     * Every segment score comes from Phase 9D (overall_score).
     * If EVERY segment has an explicit distance_km:
         route_score = sum(score_i * dist_i) / sum(dist_i) over KNOWN segments.
     * Otherwise equal weighting over the KNOWN segments is used.
     * UNKNOWN segments are NEVER scored as 100 and never counted toward
       the score; they lower completeness and confidence.
     * If every segment is UNKNOWN the route score is UNKNOWN.

  5. ROUTE CONFIDENCE
     route_confidence = mean(Phase 9D segment confidence over ALL
       segments) * (known_segment_count / total_segment_count)
       * min(per-segment data-mode factor)  [clipped to 0.05..1.0]
     mode factors: live=1.0, manual=0.9, mock=0.7, unknown=0.25.
     This is intentionally conservative: mock data, UNKNOWN segments
     and incomplete routes all lower confidence.

  6. ROUTE CATEGORY (same bands as Phase 9D)
     80-100 = GOOD | 60-79 = MODERATE | 40-59 = CAUTION |
     20-39 = POOR | 0-19 = VERY_POOR | UNKNOWN -> UNKNOWN

  7. RECOMMENDATION
     RECOMMENDED   : highest-scoring eligible route (single pick)
     ELIGIBLE      : valid route with a numeric route score
     INSUFFICIENT_DATA : zero known segments (score UNKNOWN)
     INVALID_ROUTE : nonexistent road_id, duplicate route_id, empty
                    segment list, or invalid segment_order
     Ties broken by: confidence, then known segment count, then id.
